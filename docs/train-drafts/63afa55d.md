## What we want to improve

Detect when a changed go.mod adds or retains a replace directive that maps a module to a pseudo-version or another higher-sorting target which will override normal semver selection and effectively pin module resolution as observable in the changed file.

## Why this matters

A replace that points at a pseudo-version or higher-sorting target will override module version selection and can pin or confuse upgrades. The necessary evidence — require and replace entries — is present in the changed go.mod file and therefore detectable from head-side file changes alone.

## Examples

- Library module: changed go.mod requires example.com/pkg v1.1.0 and adds replace example.com/pkg => example.com/pkg v1.1.1-20240102-abcdef, which will override semver selection and should be flagged.
- CLI module: changed go.mod requires example.org/tool v0.9.1 and retains replace to pseudo-version v0.9.1-20230202-commit that sorts higher than the tag and hides upstream tagged updates, so flag.
- Upgrade-present case: changed go.mod updates the require to v1.3.0 but still contains replace example.net/lib => example.net/lib v1.3.0-0.2024..., which will continue to override the new require and should be flagged.

## Keep it focused

- A replace that maps the required module to a local filesystem path (for example ./../localpkg or /abs/path) intentionally references unpublished local code and should not be flagged.
- A replace that redirects the required module path to a different module path (for example replacing example.com/pkg with github.com/org/forkedpkg at vX.Y.Z) is an intentional fork substitution and should not be flagged.

## Done when

- [ ] If the changed go.mod contains a replace mapping module M to a pseudo-version (vX.Y.Z-YYYYMMDDHHMMSS-commit) and the same file requires M at a lower tagged version, emit a finding that identifies the require and replace and notes the override.
- [ ] If the changed go.mod updates require M to a newer tagged version but keeps a replace whose target sorts higher than that require, emit a finding that notes the replace blocks the upgrade.
- [ ] If the changed go.mod contains a replace whose target is a local filesystem path (starting with ./, ../, or an absolute path), do not emit a finding.
- [ ] If the changed go.mod contains a replace whose target module path differs from the required module path (indicating a fork), do not emit a finding.
